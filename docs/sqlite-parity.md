# SQLite branch parity

This branch shares the starter's domain and HTTP contracts: batch-only todo commands, strict event/scopes contracts, bounded authoritative reads, atomic V2 consistency observations, protected PII, registration proposal/execution/completion, independent reset authorization/password change/completion, deletion execution/completion and ViewStore-backed progress streams.

Application persistence uses generated `database/sql` adapters with the pure Go `modernc.org/sqlite` driver. Embedded Orisun uses its SQLite runtime and the same narrow V2 adapter, boundary lifecycle and compiled indexes as command fixtures. No PostgreSQL connection is needed. Go, Orisun and tools follow `go.mod`.

The application pool enables foreign keys and a busy timeout on every connection, WAL for reader/writer coexistence and immediate write transactions before projection/cleanup reads. SQLite's database-wide writer lock replaces per-owner advisory locks while retaining transaction ownership/lifetime guards. It serializes writes across features; subscriptions remain responsible for source order. JSON patching/exact position membership preserve occurrence receipts. Native SQL tests use private databases automatically and retain the command/projection/UI test coverage.

`001_init.sql` is the complete canonical fresh-install schema, including lifecycle constraints, auth-owned profile facts and erasure markers. This starter does not automatically upgrade old schema/event histories or reset/reseed user databases. Generated code comes from `task sqlc`, `task templ` and `task css`. Use the SQLite path settings documented in the README.

Verification passed: `task test`, `task vet`, `task build`, focused race tests and `git diff --check`. Native tests include rollback, replay, transaction ownership/lifetime, erasure contention and pool configuration/persistence. An isolated live app verified pending registration without credentials, OTP validation, accepted registration/login, todo completion/reopening, auth-owned profile propagation, reset execution/completion and new-password login, then account deletion, key destruction and retained erasure evidence. The test server was stopped; only temporary database files were used. Shared domain and templ implementations match the current common contracts; UI behavior was not redesigned by the storage port.
