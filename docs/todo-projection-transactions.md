# Todo projection transactions

`contracts.go` exposes typed owner state, lifecycle facts and occurrence identity; `project.go` interprets them without generated SQL or database types. The SQLite repository owns transaction lifetime and SQL mapping.

`ProjectBatch` handles an ordered sequence in one owner transaction. Each occurrence checks full-position evidence, reads current state, folds its change, then saves state, watermark and receipt before the next event. Later reads see earlier uncommitted writes. A failure rolls back the whole batch; invalidation publishes only after commit. Replays recover routing from retained evidence without decoding old payloads.

`BEGIN IMMEDIATE` serializes all SQLite writers before reads. Context binding rejects unbound, foreign, nested and expired transactions. This provides exclusion; the serial subscriber still owns source order between batches. WAL allows readers to see the last committed state while a writer is active.

SQLite derives `completed` from the latest retained completion/reopening full positions. Native checks enforce complete lifecycle triples and reject negative/future positions. The existing commit/prepare watermark guards replacement state; JSON receipts contain only event type and full position. `json_patch` merges evidence and `json_type` checks exact position keys.

The fresh schema in `migrations/001_init.sql` contains user/list B-tree indexes and a full-position index bounding replay candidates. Arbitrary JSON membership is unindexed; SQLite has no GIN index. No receipt-only table or extra watermark is added. Queries live in `queries/todo.sql` and are generated by `task sqlc`.

Run `task test`, `task vet`, `task build` and `git diff --check`. Native SQLite tests run automatically in private files and cover retained lifecycle facts, partition equivalence, full-position identity, replay without keys, own-write visibility, independent reader isolation, actual SQL-failure rollback and transaction lifetime. No application schema reset, reseed or history rewrite is performed. Existing databases require an explicit migration/recreation decision outside this fresh starter port.
